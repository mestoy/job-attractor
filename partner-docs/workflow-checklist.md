# Outreach workflow checklist — RUN EVERY TIME, REPORT EACH STEP

> 🔒 **FIRST: `Read` `documents/HARD-INVARIANTS.md` fresh at the gate** (screen gate before surfacing; send gate before building a draft) and confirm each line — **from the file, never from in-session memory.** That card is the non-negotiables (work-arrangement-absolute, deal-breakers, honesty, zero-AI-tells, EMAIL-ONLY-no-bare-connect, etc.). This checklist is the fuller ordered flow; the card is the fast re-read that catches drift.

**Why this exists:** prose in a skill file gets skipped when a session is long or drifts. This is the non-skippable, ordered gate. **For EVERY prospect/outreach, work this top to bottom and REPORT ✅/❌/n-a for each step in your message.** A visible checklist makes a missed step obvious. Never mark a step ✅ you didn't do. Scriptable steps (1, 9, 12) are commands — run them, don't just claim them.

## Per prospect
1. **☐ Dedup** — `python3 scripts/check_dup.py "<company>" ["<boss>"]`. 🔴 ALREADY-SEEN → stop, review prior record. 🟢 NEW → continue.
2. **☐ Blocked-list** — grep `documents/blocked-employers-list.md`. Listed → DROP with reason.
3. **☐ Hard filters** (from `documents/WORKFLOW-RULES.md`, driven by kit_config screening lists) — work-arrangement incl. required-travel cadence (verify from the JD), deal-breaker industries (`INDUSTRY_VETO`), any political/values screen (`POLITICS_*`), ownership (`PE_FLAG`), recurring layoffs, always-on. Any fail → DROP.
4. **☐ Verify the role LIVE + the JD** (`python3 scripts/check_ats.py "<company>"` / careers page) + recency. Not live → radar framing.
5. **☐ Culture/leadership/news** (`documents/culture-screen-checklist.md`) — 5 recent pos+neg reviews (verbatim quotes on any flag), leadership stability, ~12-mo news, deeper-probe on any disqualifying signal.
6. **☐ Scorecard + PAUSE (ONE boss at a time)** — present a structured Boss Match Scorecard (org/product/why-this-boss 2-3 lines; screen results; flags; recommendation). WAIT for your go before deep-dive/drafting. **Per-boss build-gate:** after a batch recommendation TABLE (the overview), present EACH recommended boss as its OWN full scorecard, one at a time; you rule **build/skip per scorecard**. Do NOT batch-build all recommended targets off one table "accept" — the table is the overview + the rec; each individual scorecard is the actual build-gate. Only greenlit bosses get a résumé + line-by-line email. Note position ("1 of 4"). **Front-load research in PARALLEL, present BATCHED decision-ready choices, never a sequential tasklist:** deep-screen the candidate group and pre-research each survivor's boss (sourced accomplishment + praise angles) CONCURRENTLY and up front, so you decide across the batch in one pass rather than watching a task queue. **EXCEPTION — a confirmed, send-ready match JUMPS the batch:** push that one item straight through (phrasing pick → send) so you can establish the connection; the rest keep cooking in parallel and arrive as their own batch.
7. **☐ Deep boss-accomplishment research** (`documents/boss-research-checklist.md`) — attribution-disambiguation, primary-source verification, a verbatim citation string with URL. That citation is what feeds `mail-draft.sh --praise-source`.
8. **☐ Verify the boss** — open the real `/in/<handle>` and confirm current role (don't record "verified" from a guessed handle). Two-stage boss-praise: 3 real accomplishments → you pick; 3 phrasings → you pick.
9. **☐ Draft LINE-BY-LINE in YOUR VOICE — `Read documents/writing-style-guide.md` FRESH FIRST, before offering ANY beat option.** Do not craft voice options from in-session memory of your style — re-read your actual sends each time, then write options FROM them. **This applies to EVERYTHING written in your name, not just email beats: APPLICATION free-response answers, narratives, interview answers, thank-yous, LinkedIn text, collateral.** In a long session the sense of your voice drifts into a generic register; re-reading the real samples resets it. **ZERO AI tells** (no filler adverbs; no AI clichés; no em dashes; no spaces around slashes; `•` bullets; plus your own never-suggest words) — **audit every AskUserQuestion option PREVIEW too.** Honesty guardrails on all figures (kit_config `RETIRED` / `RETIRED_PATTERNS` / `ROLE_IMPLY`).
10. **☐ Pre-fire conformance check** — run `python3 scripts/check_outreach.py <body.txt>` (🟢 required) → PASS/FAIL on both boss-hunt format AND your writing style. Fix on fail, then fire.
11. **☐ Fire the PREFILLED draft — EMAIL ONLY** — deliver it as a draft you review and send: the `outreach-send-prep` skill (a `mailto:` prefill, any OS), or **on macOS** `scripts/mail-draft.sh --rung cold-boss --to … --bcc … --subject … --body-file … --company "<Company>" --segment "<your-segment-slug>" --praise-source "<accomplishment, URL>" --praise-phrasing "<your approved text>" --lacivita-check pass --attach "documents/cv/<Your Name> - Resume - <Company>.pdf"` (for a WARM or referred ask instead: `--rung warm --targets "Co1,Co2,Co3"` and NO praise flags, since there is no boss to praise), which additionally script-enforces the boss-hunt gates (praise-source, praise-phrasing, lacivita-check, dedup, résumé-attach). Résumé attached, visible, NEVER sent. Never desktop-drive the compose window. **When the work item includes SUBMITTING AN APPLICATION:** `open` the actual ATS application page(s) in your browser as part of executing that step (open each opening if several) so you aren't left hunting the link — the same authoritative ATS URL the liveness check already returns. (This extends "open the JD at the decision point" to "open the apply page at the apply step.") **⛔ NO same-day LinkedIn connection request** — NEVER cold-connect a boss before contact. Opening the boss's LinkedIn to *review* at decision-time is fine; opening it to bare-connect is not. **A cold boss who does not reply gets NO chase — the next action is a NEW target** (see step 14).
12. **☐ You review + send.** Never auto-send.
13. **☐ Commit everything** (after send AND drop) — `outreach_log.md`, `job_search_tracker.csv`, `documents/correspondence-log.md` (verbatim, both directions), queue-archive move, voice edits → `documents/writing-style-guide.md`, any new rule → `documents/WORKFLOW-RULES.md`.
14. **☐ Arm a follow-up ONLY for a WARM contact** — LaCivita is not much for following up. A cold boss who does not reply gets **no second touch; reach a NEW person instead.** When a warm follow-up is due (7-10 days), the channel is **EMAIL** — forward your original and add a line or two, never LinkedIn. `mail-draft.sh` now ARMS this automatically: a warm rung writes `FOLLOWUP-DUE: <date>` (+7 days) and a cold rung writes `FOLLOWUP-DUE: none`, which records the decision rather than leaving the send looking un-armed. Track cadence with `python3 scripts/check_followups.py`.

## End every working block
- **☐ Report the checklist** (which steps ✅/❌ per company) so misses are visible.
- **☐ `bash scripts/consistency-check.sh`** — the consolidated durable-storage + résumé preflight (correspondence-sync, dedup-store coverage, queue health, blocked-list, tex↔export, tmp-orphan). Fix any 🔴 hard drift before ending; ⚠️ = advisory. Also fires automatically via the Stop hook (`.claude/settings.json`).
- **☐ `scripts/backup.sh`** if meaningful changes were made.
